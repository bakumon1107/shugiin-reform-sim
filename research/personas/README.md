# 政党の選好順序（優先順位付投票の試算に向けた素材）

優先順位付投票（RCV）や単記移譲式（STV）を試算するには、有権者が候補者にどう順位を
つけたかが要る。投票用紙に残るのは第1希望だけなので、そのデータは存在しない。

ここでは「どの政党を拒否しているか」を尋ねた調査を手がかりに、**拒否されていない順**に
並べて選好順序を組み立てている。

## 何を置いていて、何を置いていないか

| | 中身 | コミット |
|---|---|---|
| `personas.json` | 比例投票先ごとの政党の**順序**だけ | する |
| `rejection_matrix.json` | 元の調査の拒否率（％） | **しない** |
| `build_personas.py` | 順序を組み立てるコード | する |

調査データそのものは出典が未確認で、`data/` のライセンス表示（総務省の結果調をもとに
作成／CC BY 4.0）とも整合しないため、リポジトリに含めない。`personas.json` は拒否率の
数値を捨てて順序だけを残すので、そこから元の調査結果を復元することはできない。

`rejection_matrix.json` を手元に置いたうえで、次を実行すると再生成できる。

```bash
python research/personas/build_personas.py
```

## 組み立て方

ある政党に比例票を投じた人たちについて、各政党の拒否率を低い順に並べる。投じた政党は
先頭に固定する。同率は党名順にして、実行するたびに結果が変わらないようにしている。

```
日本共産党に投じた人
  日本共産党 → 社会民主党 → れいわ新選組 → チームみらい → 国民民主党
  → 中道改革連合 → 日本保守党 → 日本維新の会 → 参政党 → 自由民主党
```

順序を決めるのに調査以外の仮定を持ち込まないのが利点。「拒否していない政党には比例
得票に応じて配分する」といった追加の仮定が要らない。

出てきた順序は左右の軸に沿ってきれいに並び、自由民主党と日本共産党の順序はほぼ鏡像に
なる。読み取り誤りや捏造ではないことの傍証にはなる。

## この素材の限界

**試算に使う場合、結果には必ずこれらを添えること。**

- **出典が未確認。** 調査主体・実施時期・標本数・設問文（「拒否」の定義）が分かって
  いない。グラフ画像から目視で読み取っているので、拒否率には ±2 ポイント程度の誤差が
  ある。順序だけを使うので誤差の影響は小さいが、拒否率が近い政党どうしの前後は入れ替わり
  うる。
- **拒否率は知名度と混ざっている。** 新しい政党や小さい政党は、判断材料を持つ人が少ない
  ぶん拒否率が低く出るため、実際より上位に並びやすい。チームみらいが多くの順序で上位に
  来るのはこの影響と考えられる。
- **現行制度のもとでの回答である。** 制度が変われば有権者も政党も行動を変える。この順序が
  そのまま当てはまるわけではない。
- **政党単位であって候補者単位ではない。** 小選挙区では現職かどうかや知名度が効くが、
  それは反映されていない。
- **打ち切りを表現していない。** 拒否している政党にも順位をつける前提になっている。実際
  には順位をつけずに投票用紙を打ち切る人がいるはずで、その場合は票が移譲されずに死票に
  なる。この差は結果に効きうる。

## 使い方の方針

この素材から出る議席数は、**投票結果ではなく仮定が生む数字**である。シミュレータ本体は
「現行制度で再計算すると実際の結果と完全に一致する」ことを拠り所にしているので、そちらと
同じ画面に並べて信用を巻き添えにしないこと。

使うなら次の順序が望ましい。

1. **仮定ゼロで確定する部分を先に出す。** RCV では第1選好で過半数を取った候補は、移譲が
   どう転んでも当選が動かない。まず「RCV でも変わらない議席」を確定させる。
2. **残りの範囲でこの順序を当てる。** 単一の数字ではなく、仮定を振ったときの**幅**として
   示す。幅が狭ければ頑健な知見、広ければ「この制度の結果は票ではなく仮定が決める」と
   いうこと自体が結論になる。
