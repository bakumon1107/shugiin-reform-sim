# 政党の選好順序（優先順位付投票の試算に向けた素材）

## 出典

選挙ドットコム × JX通信社の合同調査（2026年2月26日公開）。設問は
**「絶対投票したくない政党を選んでください」**（複数選択可）。

- [記事](https://go2senkyo.com/articles/2026/02/28/130298.html)
- [動画](https://www.youtube.com/watch?v=rZUJwFl6-PU)

設問が「絶対投票したくない」という強い聞き方なので、**拒否した政党には順位をつけない**
ものとして扱っている。残る候補をその層が全部拒否していれば、票は移譲されず死票になる。
「あまり支持しない」程度の設問ならこの解釈は強すぎるが、この設問なら妥当と考える。

優先順位付投票（RCV）や単記移譲式（STV）を試算するには、有権者が候補者にどう順位を
つけたかが要る。投票用紙に残るのは第1希望だけなので、そのデータは存在しない。

ここでは「どの政党を拒否しているか」を尋ねた調査を手がかりに、**拒否されていない順**に
並べて選好順序を組み立てている。

## 何を置いていて、何を置いていないか

| | 中身 | コミット |
|---|---|---|
| `personas.json` | 5%刻みに丸めた拒否率・選好順序・派生の規則 | する |
| `rejection_matrix.json` | グラフから読み取った生の値（1%刻み） | **しない** |
| `build_personas.py` | 丸めと順序の組み立て | する |

`personas.json` に入っているのは丸めた概算値で、原典の数値そのものではない。生の読み
取り値はリポジトリに含めない。`data/` は総務省の結果調をもとに作成した CC BY 4.0 の
データなので、由来の違うこの調査は同じ扱いにできない。

`rejection_matrix.json` を手元に置いたうえで、次を実行すると再生成できる。

```bash
python research/personas/build_personas.py
```

## 組み立て方

ある政党に比例票を投じた人たちについて、各政党の拒否率を低い順に並べる。投じた政党は
先頭に固定する。同率は党名順にして、実行するたびに結果が変わらないようにしている。

```
日本共産党に投じた人
  日本共産党 → 社会民主党 → れいわ新選組 → チームみらい → 国民民主党
  → 中道改革連合 → 日本保守党 → 日本維新の会 → 参政党 → 自由民主党
```

順序を決めるのに調査以外の仮定を持ち込まないのが利点。「拒否していない政党には比例
得票に応じて配分する」といった追加の仮定が要らない。

出てきた順序は左右の軸に沿ってきれいに並び、自由民主党と日本共産党の順序はほぼ鏡像に
なる。読み取り誤りや捏造ではないことの傍証にはなる。

### 移譲は層ごとに分ける

同じ党に投じた人でも拒否の仕方は違うので、票を丸ごと1つの党へ流さない。拒否率から
**入れ子モデル**で層を作り、層ごとに行き先を決める。

拒否率の高い順に政党を並べ、有権者ごとに一様乱数 u を引いて「拒否率が u より高い政党
すべて」を拒否集合とすると、各党の拒否率が正確に再現され、かつ「自民は拒否するが保守は
拒否しない」のような整合しない層が出ない。

移譲先は、その層が拒否していない中で最上位の党。残る候補を全部拒否していれば死票。
移譲された票は元の層のまま持ち回るので、次に落ちたときもその層の選好で動く。

## この素材の限界

**試算に使う場合、結果には必ずこれらを添えること。**

- **数値は目視の読み取りで、原典そのものではない。** 公開されたグラフから読んでおり
  ±2 ポイント程度の誤差がある。1%刻みで出すと原典の数値だと誤解されるので、誤差幅に
  合わせて **5%刻みに丸めてある**。拒否率が近い政党どうしの前後は入れ替わりうる。
- **実施時期・標本数・調査方法は未確認。** 公開情報に記載が見つからなかった。
- **拒否率は知名度と混ざっている。** 新しい政党や小さい政党は、判断材料を持つ人が少ない
  ぶん拒否率が低く出るため、実際より上位に並びやすい。チームみらいが多くの順序で上位に
  来るのはこの影響と考えられる。
- **現行制度のもとでの回答である。** 制度が変われば有権者も政党も行動を変える。この順序が
  そのまま当てはまるわけではない。
- **政党単位であって候補者単位ではない。** 小選挙区では現職かどうかや知名度が効くが、
  それは反映されていない。
- **層の作り方は入れ子モデルという仮定に立っている。** 誰がどの組み合わせを拒否している
  かの同時分布は公表されていない。拒否率の高い党を拒否する人は低い党も拒否する、という
  入れ子を仮定して層を作っている。各党の拒否率は正確に再現されるが、組み合わせの分布は
  こちらが置いたもの。

## 使い方の方針

この素材から出る議席数は、**投票結果ではなく仮定が生む数字**である。シミュレータ本体は
「現行制度で再計算すると実際の結果と完全に一致する」ことを拠り所にしているので、そちらと
同じ画面に並べて信用を巻き添えにしないこと。

使うなら次の順序が望ましい。

1. **仮定ゼロで確定する部分を先に出す。** RCV では第1選好で過半数を取った候補は、移譲が
   どう転んでも当選が動かない。まず「RCV でも変わらない議席」を確定させる。
2. **残りの範囲でこの順序を当てる。** 単一の数字ではなく、仮定を振ったときの**幅**として
   示す。幅が狭ければ頑健な知見、広ければ「この制度の結果は票ではなく仮定が決める」と
   いうこと自体が結論になる。
